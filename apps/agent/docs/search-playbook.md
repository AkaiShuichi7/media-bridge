# 资源搜索 Playbook（agent 找资源实操手册）

> 2026-10-18 以 MUDR-359 为样本实测验证。站点可用性会漂移，使用前先按
> 「可用源探测」复核；发现源失效时更新本文件（本文件就是源状态的权威记录）。

## 工具选择

- **用 `curl`（带浏览器 UA）直接访问，禁用 `web_extract`**——服务端抓取通道对
  这类站点会被安全策略误拦（实测 javdb.com 被判「内网地址」拒绝）。
- UA 建议普通 Chrome 桌面 UA 即可，无需登录、无需 cookie。

## 实测结论（2026-10-18）

| 站点 | 用途 | 结果 |
|---|---|---|
| `javdb.com/search?q=<番号>&f=all` | 番号详情/封面/元数据 | ✅ 200，裸 curl 可用 |
| `www.torrentkitty.tv/search/<番号>` | 磁力链接 | ✅ 200，页面内可直接提取磁链 |
| `btsow.com` | 磁力链接 | ❌ 403 |
| `sukebei.nyaa.si` / `sukebei.pantsu.cat` | 磁力链接 | ❌ 连接不可达 |
| `web_search`（番号 + magnet 关键词） | 兜底搜索 | ✅ 可用，且模型侧无内容政策阻碍 |

**注意**：JavDB 的磁链区需要登录才能看，未登录只能拿元数据——磁链去
torrentkitty 等源找，两者配合使用。

## 已验证工作流

```
1. web_search "<番号>"          → 确认番号有效、拿到标题/演员等元数据
2. curl javdb 搜索页           → 元数据交叉确认（体积、发行日期）
3. curl torrentkitty 搜索页    → 提取 magnet（正则
                                 magnet:\?xt=urn:btih:[A-Za-z0-9]{32,40}）
4. 归档查询去重                → GET /api/agent/archive/query?q=<番号>
5. 列候选给用户确认            → 标题/体积/日期/磁链，等用户挑选
6. 确认后 POST /api/tasks 提交
```

## 候选评判要点

给用户的候选列表按这些维度排序和标注：

- **体积**：单部正片通常 2-8GB；明显过小可能是预告/样片，过大可能是合集
- **C 后缀**：番号带 `-C` 表示中文字幕版，用户点名要字幕版时优先
- **合集 vs 单部**：文件名含多集标记（CD1/2、A/B）时说明是分卷，提醒用户
- **发布日期**：越新越好（老资源做种少，但 115 离线对冷资源也有效，仅作参考）

## 站点失效时的应对

1. 先按上表换备源（torrentkitty 失效 → 回退 `web_search` 找磁链聚合页）
2. JavDB 整站不可用时：番号元数据可从搜索结果摘要或其他镜像获取，不阻塞流程
3. 更新本文件的实测结论表，注明日期——**改文档，不改代码**（这正是搜索
   放在 agent 侧而非 MediaBridge 管线侧的意义）
