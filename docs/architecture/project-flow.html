1. 系统架构与数据流

Web 与 Chrome 扩展共用 FastAPI。认证中间件校验 Web 会话或扩展 Bearer Token；业务层通过 CloudService 调用 115，后台监控与整理器共享同一适配器。

Web 认证

登录后使用 HttpOnly 会话 Cookie；浏览器写操作验证 CSRF Token。

扩展认证

使用个人 mb_ 访问令牌；扩展仅在 Popup 中由用户确认后提交。

云盘边界

业务使用 CloudFile / CloudTask 等中立类型；115 原始字段由适配器隔离。

2. 离线任务完整生命周期

同步阶段只负责受理任务；下载监控与整理是后台异步流程。提交成功不等于文件已经归档。

下载状态

115 负状态 → 本地 failed；进行中任务留在轮询集合。

整理状态

有文件失败 → organize_failed；零成功 → organize_skipped；两者均保留云端任务。

成功清理

至少一个文件成功且没有失败，才标记 completed 并删除 115 离线任务。

3. 浏览器扩展捕获流程

捕获不等于提交；扩展不会静默创建任务，最后必须由用户在 Popup 明确确认。

4. 构建、配置与服务启动

生产镜像在 Node 20 阶段构建 Web，在 Python 3.12 阶段安装服务端锁定依赖。Compose 挂载配置、数据库和日志；应用启动后校验 115 cookies（失败会记录错误，但当前代码不会因此中止初始化）。
